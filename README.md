# PULSE

Платформа для медпредов (МП), региональных менеджеров (РМ), бренд-менеджеров (БМ) и мастер-аккаунта:
ежемесячный отчёт (FSS + FFE + Конверсия + Потенциал) → отправка РМ → комментарии/возврат/одобрение →
доступ мастеру/БМ → выгрузка Excel/презентации, плюс дашборды, ИИ-рекомендации, планы развития МП,
массовая загрузка продаж/таргетов из Excel, и DOC TRACKING (мониторинг врачей после конференций).

Стек:
- **Supabase** — база данных (Postgres)
- **Railway** — бэкенд (Node.js/Express)
- **Vercel** — фронтенд (React)

Это чистая установка «с нуля» — старые деплои (под именем REPLAMS/FSS Review) на этот код не влияют,
их можно спокойно удалить в Railway/Vercel, а старый Supabase-проект — оставить как архив или тоже удалить.

## Шаг 1 — База данных (Supabase)

1. Создайте **новый** проект на supabase.com (не переиспользуйте старый — так чище).
2. **SQL Editor → New query** → вставьте **весь** файл `server/schema.sql` → **Run**.
   Это единственный файл, который нужен для установки — он уже содержит все таблицы и сиды.
   (Отдельные `server/migration_00N.sql` в проекте — это история изменений для уже работающих
   старых баз; для новой установки они не нужны.)
3. Схема создаст все таблицы, каталог из 20 препаратов (с автоматической разметкой по группам
   Rhythm/Prime), группы Rhythm/Prime, и мастер-аккаунт:
   - **email:** `admin@fss.local`
   - **пароль:** `ChangeMe123!` — **обязательно смените после первого входа** (или ещё до запуска — см. ниже).
4. **Connect → Direct** → переключите на **Transaction pooler** → скопируйте строку подключения,
   замените `[YOUR-PASSWORD]` на реальный пароль базы. Понадобится на шаге 2.
   (Именно pooler, а не Direct — Railway обычно не может достучаться до Direct-подключения Supabase
   по IPv6.)

### Как сменить пароль мастер-аккаунта до запуска
```bash
node -e "console.log(require('bcryptjs').hashSync('ВАШ_ПАРОЛЬ', 10))"
```
Полученную строку вставьте вместо хэша в последней команде `insert into users ...` в `schema.sql`
перед запуском в Supabase.

## Шаг 3 — Бэкенд (Railway)

1. **railway.app** → **New Project** → **Deploy from GitHub repo** → выберите репозиторий.
2. Settings → **Source Repo → Root Directory** = `server` (обязательно, иначе сборка не поймёт,
   что собирать).
3. **Variables** → добавьте:
   - `DATABASE_URL` = строка подключения из Supabase (шаг 1.4, pooler-версия)
   - `JWT_SECRET` = любая длинная случайная строка (Railway может сгенерировать сам через `${{ secret(...) }}`)
   - `CLIENT_URL` = временно `*`, обновите на реальный домен Vercel после шага 4
   - `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` — опционально, для писем
     (напоминания по Action Plan/Конверсии, восстановление пароля). Без них платформа работает
     нормально, письма просто не отправляются.
   - `ANTHROPIC_API_KEY` — опционально, для вкладки «ИИ-рекомендации». Получить на console.anthropic.com.
4. Railway задеплоит автоматически. В **Deploy Logs** должно быть:
   `FSS Review server running on port ...`
5. Скопируйте публичный URL сервиса (Settings → Networking → Generate Domain, если ещё нет).

---

## Шаг 4 — Фронтенд (Vercel)

1. **vercel.com** → **Add New → Project** → тот же репозиторий.
2. **Root Directory** = `client`.
3. Framework Preset — Vite (определится автоматически).
4. **Environment Variables** → `VITE_API_URL` = URL Railway-бэкенда из шага 3.5 (без слэша в конце).
5. Deploy.

## Шаг 5 — финальная настройка CORS

Вернитесь в Railway → Variables → обновите `CLIENT_URL` на реальный URL Vercel → передеплой.
Без этого шага при входе будет ошибка `Failed to fetch`.

## Как пользоваться

1. Войдите как мастер (`admin@fss.local` / ваш пароль).
2. **«Пользователи»** → создайте группы (Rhythm/Prime уже есть по умолчанию, можно добавить свои) →
   создайте РМ → создайте БМ (с привязкой к группе) → создайте МП (с территорией, группой и РМ).
3. МП: месяц → FSS/FFE/Конверсия/Потенциал → «Отправить на рассмотрение РМ».
4. РМ: комментирует, одобряет или возвращает на доработку.
5. После одобрения — отчёт виден мастеру и БМ (своей группы), у всех появляются кнопки
   **«Скачать Excel»** и **«Скачать презентацию»**.

## Основные разделы

- **Отчёты / Мой отчёт** — FSS, FFE, Конверсия врачей, Увеличение потенциала, Бонус, История
- **Моя команда** (РМ) — карточки МП по группам, история, план развития с KPI
- **Дашборд** (РМ/мастер) — иерархия РМ→МП, достижения, бонусы
- **Загрузка данных** (мастер) — массовая загрузка FSS-продаж и годовых таргетов из Excel,
  с автораспределением по 15 территориям, историей загрузок и отменой
- **DOC TRACKING** (все роли, по своей зоне видимости) — мониторинг выписки препаратов врачами
  после конференций через 10 индикаторных аптек, авто-расчёт вклада в $
- **ИИ-рекомендации** — глубокий анализ динамики месяц/квартал/год (нужен `ANTHROPIC_API_KEY`)
- **Комментарии** (мастер) — все переписки по всем отчётам в одном месте
- **Профиль** — смена имени/пароля; на экране входа — восстановление пароля через мастера

## Бонус и FFE — логика, зашитая в платформу

- **FSS-бонус** (MR/Senior MR): <90% — 0; 90–99.99% — 60% ставки×достижение; 100–124.99% —
  100%×достижение; ≥125% — потолок 125% от ставки. Считается **по кварталу** (агрегация 3 месяцев),
  ставка и курс редактируются на карточке отчёта.
- **FFE-гейт**: минимум 85% среднего скора — без него бонус обнуляется, даже при выполненном FSS.
- **Non-reimbursement условие**: ≥50% плана — non-reimbursement продукты (подтверждается РМ/мастером).
- **РМ-бонус**: мультипликатор (x1.00–x2.00 по своему достижению) × средний бонус команды МП,
  при условии, что ≥50% команды квалифицировались.

## Локальный запуск для разработки

```bash
# бэкенд
cd server
cp .env.example .env   # впишите DATABASE_URL и JWT_SECRET
npm install
npm start

# фронтенд (в другом терминале)
cd client
echo "VITE_API_URL=http://localhost:8080" > .env
npm install
npm run dev
```
